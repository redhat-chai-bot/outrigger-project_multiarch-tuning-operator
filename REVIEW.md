# Code Review Instructions

## Severity Calibration

- **Critical**: Wrong API field names/types, incorrect controller behavior, broken RBAC, wrong namespace exclusion logic
- **High**: Missing error handling in reconciliation, incorrect image inspection logic, scheduling gate lifecycle issues
- **Medium**: Style issues, missing metrics, suboptimal caching, incomplete test coverage
- **Low**: Documentation, naming, cosmetic issues

## Do Not Report

These are CI-enforced or generated — do not flag in reviews:
- `zz_generated.deepcopy.go` formatting or content
- `config/crd/bases/*.yaml` — generated by controller-gen (`make manifests`)
- `config/rbac/role.yaml` — generated from kubebuilder RBAC markers
- `bundle/**` — generated by `make bundle`
- `vendor/**` — vendored dependencies
- `go.sum` changes
- gofmt/goimports violations (enforced by `make fmt`, `make goimports`)
- golangci-lint findings (enforced by `make lint`)

## Architecture Rules

1. **Mutually exclusive modes**: Only one `--enable-*` flag may be set. Do NOT add code that assumes multiple modes run in one process (`cmd/main.go:339`)
2. **Singleton CR**: `ClusterPodPlacementConfig` must be named `"cluster"`. Reject PRs adding support for multiple instances
3. **Operand RBAC is programmatic**: Permissions for pod-placement-controller/webhook are built in `internal/controller/operator/podplacement_objects.go` — NOT via kubebuilder markers on operand controllers
4. **v1beta1 is the storage version**: New API fields must go in `api/v1beta1/` with appropriate conversion in `api/v1alpha1/`
5. **CGO required**: The project depends on `containers/image` → `gpgme`. Do not introduce `CGO_ENABLED=0` build paths

## Path-Specific Rules

### `api/v1beta1/` — CRD Types
- Verify kubebuilder validation markers match documented constraints
- Check that new fields have appropriate `+optional` or `+kubebuilder:validation:Required` markers
- Ensure conversion functions updated in both `api/v1alpha1/` and `api/v1beta1/`

### `internal/controller/podplacement/` — Core Pod Placement Logic
- **High churn area** — scrutinize carefully
- Verify `shouldIgnorePod()` changes preserve hardcoded exclusions
- Check nodeAffinity mutations use correct label key (`kubernetes.io/arch`)
- Verify scheduling gate name matches `utils.SchedulingGateName`

### `internal/controller/operator/` — Operator Controller
- Verify operand resource construction matches expected RBAC, deployments, services
- Check status condition logic in `clusterpodplacementconfig_types.go`
- Verify ordered deletion logic preserved (webhook config removed before operand deployments)

### `pkg/image/` — Image Inspection
- Check registry authentication handling with pull secrets
- Verify cache invalidation logic
- Check multi-arch manifest parsing (OCI + Docker v2.2)

### `api/common/plugins/` — Plugin System
- CEL expressions must only access `self.metadata.*` — verify `assertMetadataOnly()` coverage
- Validate architecture enum values match `utils.AllSupportedArchitecturesSet()`
- NodeAffinityScoring weights must be in range 1–100
